# Error Resolution Rules

## Rule 1 — Understand before fixing

Do not modify code immediately after seeing an error.

First understand what the error is actually indicating.

---

## Rule 2 — Evaluate the problem

Determine whether the problem can be solved with the current project state.

Do not assume every error can be fixed immediately.

---

## Rule 3 — Find the root cause

Identify the actual cause before making changes.

The reported error is not always the source of the problem.

---

## Rule 4 — Avoid assumptions

Do not guess the cause of an error.

Gather enough evidence before deciding on a fix.

---

## Rule 5 — Choose the appropriate action

After identifying the cause, decide the most appropriate next step.

Possible actions may include:
- fixing the code;
- completing missing prerequisites;
- postponing the fix until another task is finished;
- informing the user that manual intervention is required.

---

## Rule 6 — Fix only the actual problem

Do not change unrelated code while resolving an error.

---

## Rule 7 — Verify the solution

After making changes, confirm that the original issue has been resolved and no new issues were introduced.

---

## Rule 8 — Explain the reasoning

Briefly explain:
- what caused the problem;
- why the chosen solution is appropriate;
- why other approaches were not selected.

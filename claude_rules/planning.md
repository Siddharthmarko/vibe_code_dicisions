# Planning Rules

Apply these rules before writing or modifying code.

---

## Rule 1 — Understand the task

Understand the requirement before coding.

Ask for clarification if important information is missing.

---

## Rule 2 — Review existing code

Review the related files, architecture, and coding style before making changes.

---

## Rule 3 — Explain the plan

Briefly explain:

- what will be implemented;
- which files will change;
- why.

---

## Rule 4 — New files require approval

Do not create new files without explaining:

- why they are needed;
- their responsibility.

Wait for user approval.

---

## Rule 5 — Explain important decisions

When multiple reasonable approaches exist, briefly explain:

- the chosen approach;
- the main alternative;
- why the chosen approach is better.

Skip obvious decisions.

---

## Rule 6 — Stay within scope

Implement only the requested requirement.

Do not add extra features, refactoring, or optimizations unless requested.

---

## Rule 7 — Summarize changes

After completing the task, briefly mention:

- what was implemented;
- which files changed;
- any deferred work or limitations.
